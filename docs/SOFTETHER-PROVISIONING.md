# SoftEther account provisioning and credential delivery

## Scope
Second VPN-host worker milestone: claim `softether_account` jobs and create the
per-device SoftEther identity in the isolated `CSL` Virtual Hub. The DHCP worker
boundary is preserved: SoftEther support is opt-in via environment configuration.

## Credential model
- The device credential is client-generated; the server stores only its SHA-256 hash.
- A separate per-device SoftEther password is generated by the control plane on first
  need (worker claim or device credential fetch). It is never the device credential.
- At rest the password is sealed with AES-256-GCM using `CSLVPN_SECRETS_KEY` (32 bytes).
  The AAD is the device UUID, so a ciphertext cannot be replayed for another device.
- The provisioning outbox payload never contains the secret.
- The secret is delivered only over HTTPS: to the authenticated provisioner in the claim
  response, and to the authenticated device via `GET /api/v1/device/vpn-credentials`
  once `provisioning_status = ready`.

## Username derivation
`softether_username = "dev-" + hex(sha256(device_id)[:10])` (24 chars, fits SoftEther
limits). Deterministic, unique per device, enforced by a UNIQUE constraint.

## Agent execution rules
- Fixed absolute `vpncmd` path; arguments passed as argv; no shell strings.
- Hub admin password is read from a root-owned `0600` file, never from argv or env.
- Passwords are fed to vpncmd via stdin and redacted from any logged output.
- EnsureAccount is idempotent: UserGet -> UserCreate if absent -> UserPasswordSet ->
  UserPolicySet max_connection=1. Retries after partial failure are safe; the device
  stays blocked until the job completes.
- No SecureNAT, no Local Bridge, no host forwarding changes.

## Environment variables (agent)
| Variable | Default | Purpose |
|---|---|---|
| CSLVPN_SOFTETHER_VPNCMD | (unset = disabled) | Absolute path to vpncmd binary |
| CSLVPN_SOFTETHER_SERVER | 127.0.0.1:443 | SoftEther admin listener |
| CSLVPN_SOFTETHER_HUB | CSL | Virtual Hub name |
| CSLVPN_SOFTETHER_ADMIN_PASSWORD_FILE | /etc/cslvpn/softether-hub-admin.password | Root-owned 0600 file |

## Server environment
| Variable | Purpose |
|---|---|
| CSLVPN_SECRETS_KEY | 64 hex chars (32 bytes) for AES-256-GCM sealing |

Generate: `openssl rand -hex 32`

## Validation required on pinned build (4.44-9807-rtm) before production
1. vpncmd reads the connection password and the UserPasswordSet password/confirm from
   stdin in the exact order implemented here.
2. The security policy name for concurrent-session limiting is `max_connection`.
3. The actual SoftEther administration listener host:port matches CSLVPN_SOFTETHER_SERVER.
Record socket inspection and vpncmd transcripts in the deployment log.
